# Roadmap

## Alpha 0.1 — autonomous engineering foundation

- [x] shared task, finding, event, approval, and state-transition contracts
- [x] Ollama local-model transport with bounded tool loops
- [x] SQLite task/event/approval/finding persistence
- [x] explicit ASK / PLAN / EDIT / AGENT permission modes
- [x] approved repository access boundary
- [x] isolated task-scoped Git worktrees for mutation
- [x] bounded file patching and command execution
- [x] Git status/diff inspection
- [x] deterministic quick/full verification profiles
- [x] bounded evidence-driven repair loops
- [x] fresh-context independent review with persisted findings
- [x] explicit non-destructive patch/commit delivery
- [x] Windows desktop launcher and tray lifecycle
- [x] TypeScript/JavaScript symbol search, outlines, definitions, references, implementations, quick info, and diagnostics
- [x] language intelligence integrated into the canonical ToolBroker and repository access policy
- [x] one root npm application and one CI verification contract

## Alpha 0.2 — browser-driven Web Engineer

- [x] controlled browser runtime for locally running applications
- [x] DOM inspection and element interaction
- [x] browser console error/warning capture
- [x] failed request and network evidence
- [x] screenshot capture and before/after evidence
- [x] responsive viewport verification
- [x] accessibility checks
- [x] browser evidence attached to verification/review/repair loops
- [x] optional local vision-model review of screenshots
- [ ] visual/regression verification profiles for web tasks

## Alpha 0.3 — software engineering team

- [ ] explicit architect / implementer / reviewer / verifier discipline routing
- [ ] frontend, backend, database, security, QA, DevOps, and infrastructure specialist roles
- [ ] Python / Rust / Go / C# language-server providers
- [ ] richer code graph and call-hierarchy context
- [ ] persistent repository memory beyond the bounded structural map
- [ ] named checkpoints and task continuation history
- [ ] review-decision history across task continuations
- [ ] security-focused verification and dependency analysis
- [ ] task decomposition across independent specialist contexts

## Alpha 0.4 — engineering organization

- [x] native Windows desktop shell
- [ ] multiple local-model profiles and model routing
- [ ] resource/cost telemetry for local inference
- [ ] stronger OS-level sandboxing for commands and browsers
- [ ] reusable project playbooks and team policies
- [ ] optional cloud-model escalation behind explicit policy

## 1.0 direction

BORG should operate as an inspectable local engineering organization: specialists can plan, implement, test, review, repair, and deliver across software disciplines while every mutation, command, verification result, review finding, and delivery action remains explicit and attributable.
